# whiskerd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show Ajazz and Keychron dongle-mouse battery levels in the GNOME top bar, using a tiny Rust
daemon and a GNOME Shell extension.

**Architecture:**
- The Rust daemon `whiskerd` runs as a systemd user service. It runs one `poll(2)` loop over three
  inputs:
  - a netlink uevent socket, for hotplug;
  - the Keychron receiver's hidraw fd, for its pushed `54 e2` reports;
  - a 300 s timeout, for the Ajazz feature-report query.
- It writes `$XDG_RUNTIME_DIR/whiskerd.json` atomically.
- A GNOME 50 ESM extension watches that file with `Gio.FileMonitor` and renders one panel item per
  mouse.

**Tech Stack:** Rust (edition 2021; only dependency `libc`), GJS ESM extension for GNOME Shell 50,
udev, systemd user units.

**Spec:** `docs/superpowers/specs/2026-11-20-whiskerd-design.md`

## Global Constraints

- The only runtime crate is `libc`. No async runtime, no serde, no threads.
- Read-only toward the mouse. Never send any command other than these two:
  - Ajazz status query `0c 01 20 00 <seq> 00 00…`;
  - Keychron receiver slot query `b2 00…` on interface 3.
- Ajazz: `248a:5b2f`, interface 1, feature report `0x0C`, 33 bytes; poll interval 300 s.
- Keychron: `3434:d031`, interface 1, input report `0x54`; only `byte[1]==0xE2 && byte[6]==2 && byte[7]==2` carries
  battery `byte[5]`.
- Output path `$XDG_RUNTIME_DIR/whiskerd.json`, falling back to `/run/user/<uid>/whiskerd.json`.
  JSON keys are exactly `id,name,battery,charging,connected,updated`.
- Names:
  - binary `whiskerd`;
  - unit `whiskerd.service`;
  - udev rule `70-whiskerd.rules`;
  - extension UUID `whiskerd@zamiul-rashid`.
- Target: under 2 MB RSS and 0 % CPU while idle; `MemoryMax=16M` in the unit.

## Review Focus

1. **Dongle unplugged while its fd is open.** `poll` reports `POLLHUP`/`POLLERR`, or `read` returns
   `ENODEV`. Expected: the device is dropped and the JSON is rewritten, with no busy loop. Covered by
   Task 5, Step 4 (manual unplug check, including CPU).
2. **Non-battery `0x54` reports.** Expected: `54 e4 …`, `54 00 …` and the zero-filled
   `54 e2 01 01 00 00 …` are ignored, and the last value is kept. Covered by Task 1 tests.
3. **Ajazz reply not ready or bogus.** Expected: `rx[2] != 0x20`, `rx[6] == 0`, or battery above
   100 gives no reading, and the last value is kept. Covered by Task 1 tests.
4. **`XDG_RUNTIME_DIR` unset.** Expected: the daemon falls back to `/run/user/<uid>`. Covered by Task 2
   test `runtime_path_falls_back`.
5. **hidraw permission denied** (udev rule not installed yet). Expected: one log line per device and
   no crash or spin; the device is listed with `battery: null`. Covered by Task 5, Step 4.

### Task 1: Crate scaffold and protocol parsers

**Files:**
- Create: `Cargo.toml`, `src/main.rs` (stub `fn main() {}`), `src/drivers/mod.rs`,
  `src/drivers/ajazz.rs`, `src/drivers/keychron.rs`

**Interfaces:**
- Produces in `drivers/mod.rs`:
  - `pub struct Reading { pub battery: u8, pub charging: Option<bool> }`, deriving
    `Debug, Clone, Copy, PartialEq`.
  - `pub enum Kind { Ajazz, Keychron }`, deriving `Debug, Clone, Copy, PartialEq, Eq`.
  - `impl Kind`:
    - `pub fn vid(self) -> u16`;
    - `pub fn pid(self) -> u16`;
    - `pub fn iface(self) -> u8`, which is 1 for both kinds;
    - `pub fn id(self) -> &'static str`, which returns `"ajazz-248a5b2f"` or `"keychron-3434d031"`;
    - `pub const ALL: [Kind; 2]`.
- Produces in `drivers/ajazz.rs`:
  - `pub const REPORT_LEN: usize = 33`;
  - `pub fn request(seq: u8) -> [u8; REPORT_LEN]`;
  - `pub fn parse(rx: &[u8]) -> Option<(Reading, String)>`, where the `String` is the 4-char tag
    (e.g. `"M184"`, trailing NULs trimmed).
- Produces in `drivers/keychron.rs`:
  - `pub fn parse_event(report: &[u8]) -> Option<Reading>`, where `report[0]` is the report ID `0x54`
    and the `Reading` has `charging: None`;
  - `pub fn parse_slots(r: &[u8]) -> Option<(u16, bool)>`, which takes the iface-3 reply
    `b2 <n> <vid lo> <vid hi> <pid lo> <pid hi> <connected>` and returns (mouse PID, connected) for
    the first slot whose VID is 0x3434;
  - `pub fn model_name(pid: u16) -> &'static str`, which maps
    - `d03f` → `"Keychron M6"`;
    - `d032` and `d033` → `"Keychron M3"`;
    - `d035` → `"Keychron M1"`;
    - `d03b` → `"Keychron M2"`;
    - `d036` and `d03e` → `"Keychron M3 mini"`;
    - `d044` → `"Keychron M7"`;
    - anything else → `"Keychron mouse"`.

### Task 4: hidraw I/O for both receivers

**Files:**
- Create: `src/hidraw.rs`; Modify: `src/main.rs` (`mod hidraw;`)

**Interfaces:**
- Consumes: `drivers::{ajazz, keychron, Reading}`.
- Produces:
  - `pub fn hidioc_sfeature(len: usize) -> libc::c_ulong` and
    `pub fn hidioc_gfeature(len: usize) -> libc::c_ulong`, computed as
    `_IOC(_IOC_WRITE|_IOC_READ, 'H', 0x06|0x07, len)`;
  - `pub fn ajazz_query(devnode: &Path, seq: u8) -> std::io::Result<Option<(Reading, String)>>`,
    which opens the node read-write, sends the SET, sleeps 30 ms, then GETs. It retries the GET once
    after a further 30 ms when `parse` returns `None`.
  - `pub fn keychron_open(devnode: &Path) -> std::io::Result<std::fs::File>`, which opens with
    `O_RDONLY|O_NONBLOCK|O_CLOEXEC`;
  - `pub fn keychron_slots(iface3: &Path) -> std::io::Result<Option<(u16, bool)>>`, which writes
    `[0x00, 0xB2, 0…]` (33 bytes) and reads with `poll` (500 ms timeout) until a report starting with
    `0xB2` arrives. It parses that with `keychron::parse_slots`.

### Task 5: Event loop with hotplug

**Files:**
- Create: `src/netlink.rs`; Modify: `src/main.rs`

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `netlink::open() -> io::Result<OwnedFd>`, which binds a `NETLINK_KOBJECT_UEVENT` socket to
    multicast group 1 with `SOCK_NONBLOCK|SOCK_CLOEXEC`;
  - `netlink::drain_has_hidraw(fd) -> bool`, which reads every pending message and returns true if any
    contains `SUBSYSTEM=hidraw`;
  - `pub fn is_hidraw_event(msg: &[u8]) -> bool`, the pure part, which is unit tested.

**Loop rules:**
- At startup, and on each hidraw uevent, run `scan`:
  - drop devices that disappeared and add new ones;
  - for a new Ajazz device, query it at once;
  - for a new Keychron device, open interface 1 and call `keychron_slots` to get the name and the
    connected flag.
- The `poll` set is the netlink fd plus every open Keychron fd. The timeout is the time until the next
  Ajazz query, which runs every 300 s.
- On Keychron `POLLIN`, read reports until `EAGAIN` and run `parse_event` on each. On `POLLHUP`,
  `POLLERR` or `ENODEV`, drop that device.
- On a failed Ajazz query, mark it `connected: false` and keep the last battery.
- When opening a node fails with `EACCES`, log `whiskerd: no access to <node> (install the udev rule)`
  once per node, and still list the device with `battery: null`.
- Rewrite the JSON only when the rendered string changes. Log to stderr only on add, remove and errors.

- [ ] **Step 1: Write failing test** `is_hidraw_event`:
  - `b"add@/devices/.../hidraw/hidraw11\0ACTION=add\0SUBSYSTEM=hidraw\0"` → `true`;
  - the same with `SUBSYSTEM=input` → `false`.
- [ ] **Step 2:** Run `cargo test netlink`. Expected: FAIL.
- [ ] **Step 3:** Implement `netlink.rs` and the loop in `main.rs`. Use `std::time::SystemTime` for
  `updated`, and `libc::getuid()` with `std::env::var("XDG_RUNTIME_DIR")` for `runtime_path`.
- [ ] **Step 4: Hardware check** (run as root until Task 6):
  1. Run `sudo XDG_RUNTIME_DIR=/run/user/1000 ./target/release/whiskerd`.
  2. `cat /run/user/1000/whiskerd.json` shows Ajazz with a battery value.
  3. Switch the M6 off and on. The Keychron battery appears within 2 s.
  4. Unplug the Ajazz dongle. Its entry disappears within 1 s; plug it back and it returns.
  5. `ps -o rss,pcpu -C whiskerd` shows RSS under 2048 KB and 0.0 % CPU after 1 minute idle.
  6. Run it as your normal user (without sudo). You get one "no access" log line per node and no spin
     (`pcpu` 0.0).
- [ ] **Step 5: Commit** with `git commit -m "feat: poll loop with netlink hotplug"`.
